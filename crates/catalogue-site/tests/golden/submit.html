Submit

Every change to the catalogue starts as a GitHub issue form. Pick the form for your change.

  • Submit a project: Propose a new library or app for the catalogue.
  • Correctness report: Report a wrong fact on an entry.
  • Supersedes or fork: Report that one entry replaces another.
  • Product or demo: Set whether an entry is a product or a demo.
  • Topic change: Change the topics of an entry.
  • Featured demotion: Approve moving a Featured entry to a lower tier.
  • Featured approval: Approve Featured for an org-affiliated entry.
  • Maintainer statement: State whether a project is maintained or finished.

Approval

A maintainer listed in data/maintainers.toml must approve the issue.

Approval is the approved label on the issue. The bot accepts that label only from a listed maintainer.

After approval, the bot opens a pull request with the data change. Merging that pull request applies it.

An ml-rust organization member never approves a judgment on an org-affiliated entry.

Every judgment is public: the issue, your login, the evidence and the approver appear on the entry page.

Read the rules before you file a judgment.
